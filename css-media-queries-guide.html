Anatomia di una media query

Una media query è una condizione: "applica queste regole solo se il dispositivo ha queste caratteristiche". È lo strumento alla base del responsive design, ma non riguarda solo la larghezza dello schermo: può chiedere al browser se c'è un mouse, se l'utente preferisce il tema scuro, se la pagina sta per essere stampata.

@mediala regola (at-rule)
screentipo di media (facoltativo)
andoperatore logico
(min-width: 768px)media feature: la condizione, sempre tra parentesi
{ … }regole applicate se è vera
@media screen and (min-width: 768px) {
    .menu {
        flex-direction: row;
    }
}
Senza questa riga nell'HTML il responsive non funziona su mobile:
<meta name="viewport" content="width=device-width, initial-scale=1.0">
Senza il meta viewport lo smartphone finge di essere largo circa 980px e rimpicciolisce la pagina: le tue media query per "mobile" non scatteranno mai.

Approfondimento ispirato a A Complete Guide to CSS Media Queries di CSS-Tricks.

Tipi di media

Il tipo di media indica la categoria di dispositivo. Oggi ne sopravvivono tre (gli altri, come tv o handheld, sono deprecati):

allTutti i dispositivi. È il default: se ometti il tipo, è come scrivere all.
screenSchermi: computer, tablet, smartphone, TV.
printStampa e anteprima di stampa (anche "Salva come PDF").

Un foglio di stile per la stampa

Pochi ci pensano, ma ricette, biglietti, fatture e articoli vengono stampati. Con @media print si eliminano menu e banner e si ottimizza il testo per la carta.

@media print {
    nav, footer, .banner, .no-print {
        display: none;                 /* Via tutto ciò che sulla carta non serve */
    }
    body {
        font-size: 12pt;               /* Sulla carta si ragiona in punti */
        color: #000;
        background: #fff;
    }
    a[href^="http"]::after {
        content: " (" attr(href) ")";  /* Mostra l'URL dei link esterni */
        font-size: 0.8em;
    }
    h2, h3 {
        break-after: avoid;            /* Il titolo non resta orfano a fine pagina */
    }
}

Mobile first e scelta dei breakpoint

Mobile first consigliato

Stili base per lo schermo piccolo, poi si aggiunge con min-width.

.griglia {
    display: grid;
    gap: 1rem;
}
@media (min-width: 768px) {
    .griglia {
        grid-template-columns: 1fr 1fr;
    }
}
@media (min-width: 1200px) {
    .griglia {
        grid-template-columns: repeat(4, 1fr);
    }
}

Desktop first

Stili per il desktop, poi si toglie con max-width.

.griglia {
    display: grid;
    grid-template-columns: repeat(4, 1fr);
    gap: 1rem;
}
@media (max-width: 1199px) {
    .griglia {
        grid-template-columns: 1fr 1fr;
    }
}
@media (max-width: 767px) {
    .griglia {
        grid-template-columns: 1fr;
    }
}

Perché mobile first? Il CSS per il mobile è quasi sempre il più semplice (una colonna, elementi impilati): partire da lì significa scrivere meno codice e sovrascrivere meno regole. E costringe a decidere cosa è davvero importante.

Quali breakpoint scegliere?

Non esistono breakpoint "giusti": i dispositivi sono migliaia e cambiano ogni anno. La regola professionale è: il breakpoint lo decide il contenuto, non il dispositivo. Allarga lentamente la finestra: quando il layout comincia a stare male (righe di testo troppo lunghe, card troppo larghe, spazi vuoti), lì serve un breakpoint.

Come punto di partenza vanno benissimo quelli di Bootstrap (576px, 768px, 992px, 1200px, 1400px), che trovi nella tabella della Guida CSS Base. Due o tre breakpoint bastano quasi sempre.

Operatori logici: and, virgola, not, only

/* AND: tutte le condizioni devono essere vere */
@media (min-width: 768px) and (orientation: landscape) { ... }

/* OR: la virgola separa query alternative (basta che una sia vera) */
@media (max-width: 575px), print { ... }

/* OR (sintassi moderna, dentro la stessa query) */
@media (max-width: 575px) or (orientation: portrait) { ... }

/* NOT: nega l'intera query */
@media not print { ... }                  /* tutto tranne la stampa */
@media not (hover: hover) { ... }         /* dispositivi senza hover */

/* ONLY: nasconde la query ai browser antichissimi. Oggi è superfluo */
@media only screen and (min-width: 768px) { ... }
Nota: only screen and si trova ancora in moltissimi tutorial e template. Non fa danni, ma non serve più: puoi scrivere semplicemente @media (min-width: 768px).

La nuova sintassi a intervalli

min-width e max-width confondono spesso: "min-width: 768px" significa "larghezza minima 768", cioè "da 768 in su". La sintassi moderna usa i normali simboli matematici, molto più leggibili. È supportata da tutti i browser moderni.

Sintassi classicaSintassi a intervalliSignificato
(min-width: 768px)(width >= 768px)da 768px in su
(max-width: 767.98px)(width < 768px)sotto i 768px
(min-width: 768px) and (max-width: 1023.98px)(768px <= width < 1024px)solo tablet

Il problema del pixel di confine

Con la sintassi classica, (max-width: 768px) e (min-width: 768px) sono entrambe vere a 768px esatti: le due regole si scontrano. Per questo nei framework trovi valori strani come 767.98px. Con gli intervalli il problema sparisce: < esclude il confine, >= lo include.

@media (width < 768px)  { /* mobile */  }
@media (width >= 768px) { /* tablet+ */ }   /* nessuna sovrapposizione */

Hover, pointer, orientamento e risoluzione

La larghezza non dice tutto: un tablet di 1024px può non avere il mouse, un portatile con touchscreen ha entrambi. Queste media feature chiedono come l'utente interagisce:

Media featureValoriDomanda
hoverhover | noneIl dispositivo principale può "passare sopra" gli elementi?
pointerfine | coarse | noneIl puntatore è preciso (mouse) o grossolano (dito)?
any-hover, any-pointercome sopraLo stesso, ma considerando qualsiasi dispositivo collegato
orientationportrait | landscapeLo schermo è più alto che largo, o viceversa?
aspect-ratioes. 16/9Il rapporto larghezza/altezza della finestra
resolutiones. 2dppxQuanti pixel fisici per pixel CSS (schermi retina)

Esempio: azioni visibili solo al passaggio del mouse... se c'è un mouse

Nascondere i bottoni finché non si passa sopra la card è elegante su desktop, ma su touch quei bottoni diventerebbero irraggiungibili. Soluzione: nasconderli solo dove l'hover esiste.

/* Di default (touch) le azioni sono sempre visibili */
@media (hover: hover) and (pointer: fine) {
    .card .azioni { opacity: 0; }
    .card:hover .azioni,
    .card:focus-within .azioni { opacity: 1; }
}

/* Su touch, aree cliccabili più grandi */
@media (pointer: coarse) {
    .bottone { min-height: 44px; }
}
Card di prova
Con il mouse: passa sopra. Sul telefono i bottoni sono già visibili.

Preferenze dell'utente

Queste media query leggono le impostazioni del sistema operativo. Rispettarle è una questione di accessibilità e di rispetto per chi naviga.

/* Tema scuro del sistema */
@media (prefers-color-scheme: dark) {
    :root {
        --sfondo: #121212;
        --testo: #e9ecef;
    }
}

/* Movimento ridotto: per chi soffre di vertigini o disturbi vestibolari */
@media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
        animation-duration: 0.01ms !important;
        animation-iteration-count: 1 !important;
        transition-duration: 0.01ms !important;
        scroll-behavior: auto !important;
    }
}

/* Più contrasto richiesto */
@media (prefers-contrast: more) {
    .bottone { border: 2px solid currentColor; }
}

/* Modalità a colori forzati (es. contrasto elevato di Windows) */
@media (forced-colors: active) {
    .icona-decorativa { forced-color-adjust: auto; }
}
Combinare sistema e scelta manuale: questo stesso manuale parte da prefers-color-scheme e poi lascia scegliere con il bottone in basso a destra, salvando la scelta. Il codice è in js/theme-toggle.js. Per il movimento vedi anche Motion e Micro-interazioni.

Media queries nell'HTML

Le media queries non vivono solo nel CSS: l'attributo media le porta anche nell'HTML.

<!-- Un foglio di stile caricato solo per la stampa -->
<link rel="stylesheet" href="stampa.css" media="print">

<!-- Immagini diverse (art direction): ritaglio verticale su mobile -->
<picture>
    <source media="(width >= 768px)" srcset="hero-orizzontale.jpg">
    <img src="hero-verticale.jpg" alt="Studenti in laboratorio">
</picture>

<!-- Logo diverso per il tema scuro -->
<picture>
    <source media="(prefers-color-scheme: dark)" srcset="logo-chiaro.svg">
    <img src="logo-scuro.svg" alt="Accademia di Belle Arti">
</picture>

Il browser scarica comunque il CSS con media="print", ma con priorità bassa, senza bloccare la visualizzazione della pagina. Per <picture> e srcset vedi la Guida HTML.

Media queries in JavaScript: matchMedia()

A volte serve sapere in JavaScript se una media query è vera: per esempio per avviare un carosello solo su desktop o per disattivare un'animazione GSAP con prefers-reduced-motion. window.matchMedia() usa esattamente la stessa sintassi del CSS.

const desktop = window.matchMedia('(width >= 992px)');

// Lettura immediata: true o false
if (desktop.matches) {
    console.log('Siamo su desktop');
}

// Reagire quando cambia (ridimensionamento, rotazione...)
desktop.addEventListener('change', (evento) => {
    if (evento.matches) {
        avviaMenuDesktop();
    } else {
        avviaMenuMobile();
    }
});

// Rispettare il movimento ridotto anche nelle animazioni JS
const menoMovimento = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
gsap.to('.box', { x: 200, duration: menoMovimento ? 0 : 1 });
Meglio di resize: l'evento resize scatta decine di volte al secondo mentre si ridimensiona; change di matchMedia scatta solo quando si attraversa il breakpoint. La tabella della sezione 2 funziona proprio così.

Organizzare il codice

Due approcci: raccogliere tutte le media query in fondo al file, oppure scriverle accanto al componente a cui si riferiscono. Il secondo è più facile da mantenere: quando modifichi la card, trovi tutto nello stesso punto. Con il nesting nativo del CSS (o con SASS) diventa ancora più comodo:

.card {
    padding: 1rem;
    font-size: 1rem;

    @media (width >= 768px) {
        padding: 2rem;          /* Vale per .card da 768px in su */
    }

    @media (prefers-reduced-motion: no-preference) {
        transition: transform 0.2s;
    }
}

I breakpoint però non si possono (ancora) mettere in variabili CSS: @media (width >= var(--tablet)) non funziona. Con SASS invece sì, con variabili e mixin: vedi SCSS/SASS.

Quando le media queries non servono

Il CSS moderno ha strumenti che si adattano da soli, spesso con meno codice e risultati più fluidi. Prima di aggiungere un breakpoint chiediti se basta uno di questi:

EsigenzaInvece di una media query
Titoli più piccoli su mobileTipografia fluida: font-size: clamp(1.5rem, 1rem + 3vw, 3rem) → CSS Moderno
Griglia di card da 1 a 4 colonnerepeat(auto-fit, minmax(250px, 1fr)) → Grid in dettaglio
Elementi in fila che vanno a capoflex-wrap: wrap + flex: 1 1 250px → Flexbox in dettaglio
Un componente che cambia in base allo spazio che ha, non allo schermo (la stessa card in sidebar e nel contenuto)Container queries (@container) → CSS Moderno
Larghezza massima del contenitorewidth: min(100% - 2rem, 1200px)
