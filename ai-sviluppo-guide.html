1. Il Modello è il Motore, l'Harness è l'Auto

Nella prima pagina abbiamo visto che un modello, da solo, non naviga sul web, non ricorda e non agisce. Eppure gli assistenti che usiamo fanno tutte queste cose. Il motivo è che ciò che usiamo non è mai il modello "nudo".

Il modello = il motore

La "mente" che legge testo e genera testo. Un motore potentissimo, ma da solo su un banco di prova non va da nessuna parte.

L'harness = l'auto

Il software costruito attorno al modello: istruzioni di sistema, strumenti, permessi, memoria e il ciclo di lavoro. Volante, ruote, freni e navigatore che trasformano la potenza in movimento utile.

Per questo lo stesso modello si comporta in modo diverso a seconda di dove lo usi:

Dove Cosa può fare l'harness
App di chat (web o telefono) Conversare, cercare sul web, leggere file caricati, generare immagini o documenti. Non tocca il tuo computer.
Editor di codice con AI Vede i file del progetto aperto, suggerisce completamenti mentre scrivi, modifica più file su richiesta.
Agente da terminale Esplora tutta la cartella, esegue comandi, avvia test, usa Git: lavora su un compito per molti passaggi in autonomia, chiedendo il permesso per le azioni rischiose.

1.1 Il Ciclo Agentico

Un agente è un modello che lavora in un ciclo: invece di rispondere una volta sola, ragiona, agisce con uno strumento, guarda cosa è successo e decide il passo successivo. Ripete finché il compito non è completato.

Esempio: "La pagina contatti non è responsive, sistemala"

  1. Pensa: devo trovare i file della pagina contatti.
  2. Strumento: cerca i file → trova contatti.html e css/style.css. Osserva: la griglia ha larghezze fisse in px.
  3. Pensa: sostituisco con una griglia fluida e una media query. Strumento: modifica il file.
  4. Strumento: apre la pagina in un browser a 375px di larghezza. Osserva: il form ora va su una colonna, ma un bottone esce dal bordo.
  5. Pensa → Strumento → Osserva: corregge il bottone, ricontrolla. Finito? Sì: riassume le modifiche fatte.

2. La Memoria, su Tre Livelli

1 Context window

Memoria a breve termine: la conversazione e i file letti in questa sessione. Si riempie: gli harness la riassumono o la "compattano" quando è piena, e qualche dettaglio si perde. Per i compiti lunghi conviene aprire sessioni nuove e mirate.

2 Memoria persistente

Le app di chat possono salvare fatti su di te (studi web design, preferisci risposte brevi…) e rimetterli nel contesto delle chat successive. Di solito puoi vederli, modificarli e cancellarli dalle impostazioni.

3 File di istruzioni

Un file di testo nella cartella del progetto, come CLAUDE.md o AGENTS.md, che l'agente legge all'inizio di ogni sessione: il "manuale del progetto" per un collaboratore che ogni mattina arriva senza ricordare nulla.

Esempio di CLAUDE.md per un progetto del corso

È scritto in Markdown, conciso e concreto. Contiene ciò che l'agente non può dedurre leggendo il codice: scopo, convenzioni, comandi, divieti.

# Sito "Obiettivo Aperto" – associazione fotografica

## Progetto
Sito vetrina di un'associazione che organizza corsi e mostre di fotografia.
Pubblico: adulti 30-65 anni, poco esperti di tecnologia → chiarezza prima di tutto.
Progetto d'esame di Web Design 2 (ABA Macerata).

## Stack
- HTML5, CSS3, JavaScript ES6+ (niente framework JS)
- Bootstrap 5.3 da CDN, Bootstrap Icons
- PHP 8 solo per il form contatti (contatti.php)
- Sviluppo locale con WAMP: http://localhost/obiettivo-aperto/

## Struttura
- *.html nella root, una pagina per sezione
- css/style.css: stili custom, variabili CSS in :root
- js/main.js: menu, galleria, validazione form
- img/: immagini ottimizzate in WebP, max 300 KB

## Convenzioni
- lang="it", HTML semantico (header, nav, main, footer)
- Classi custom in BEM: .galleria__foto--attiva
- Mobile-first: media query solo con min-width
- Ogni immagine ha alt descrittivo; i link esterni hanno rel="noopener noreferrer"
- Testi in italiano, tono caldo, si dà del tu

## Verifiche prima di dire "fatto"
- HTML valido su validator.w3.org
- Controllo a 375px, 768px e 1280px
- Navigazione da tastiera funzionante

## Cosa NON fare
- Non aggiungere librerie o npm senza chiedere
- Non modificare i testi delle pagine: sono approvati dal cliente
- Non scrivere credenziali nel codice: stanno in config.php, escluso da Git
- Non fare commit o push senza mia richiesta esplicita
Curiosità: anche questo manuale ha i suoi file AGENTS.md e CLAUDE.md. Puoi leggerli nel repository su GitHub.

3. I Tool (Strumenti)

I tool sono le "mani" dell'agente: ricerca web, esecuzione di codice, lettura e scrittura di file, browser, terminale, e qualsiasi servizio esterno gli venga collegato.

Punto chiave: il modello non esegue nulla direttamente. Produce solo testo. Quando vuole usare uno strumento, scrive una richiesta strutturata (una tool call); è l'harness che la esegue davvero, magari dopo aver chiesto il tuo permesso, e gli restituisce il risultato. È come un architetto che non va in cantiere ma scrive istruzioni precise all'impresa e legge il rapporto di ritorno.

Una tool call passo per passo

Esempio semplificato a scopo didattico: ogni piattaforma usa un formato leggermente diverso, ma la logica è la stessa.

1. L'harness descrive al modello lo strumento disponibile

{
  "name": "meteo_attuale",
  "description": "Restituisce il meteo attuale di una città italiana",
  "input_schema": {
    "type": "object",
    "properties": {
      "citta": { "type": "string", "description": "Nome della città" }
    },
    "required": ["citta"]
  }
}

2. L'utente chiede: "Domani faccio foto all'aperto a Macerata, com'è il tempo?" e il modello risponde con una tool call

{
  "type": "tool_use",
  "name": "meteo_attuale",
  "input": { "citta": "Macerata" }
}

3. L'harness esegue la richiesta (es. chiama un'API meteo) e restituisce il risultato

{
  "type": "tool_result",
  "content": "Macerata: 18°C, nuvoloso, vento debole"
}

4. Il modello usa il risultato per rispondere

"Ora a Macerata ci sono 18°C con cielo nuvoloso: una luce morbida, ottima per i ritratti. Per domani, però, ti conviene controllare le previsioni: io vedo solo il meteo attuale."

Nota il formato: è JSON, lo stesso che hai usato con le API nella guida API & CRUD.

4. MCP: Model Context Protocol

Ogni assistente ha bisogno di collegarsi a molti servizi (GitHub, Figma, Google Drive, database…). Senza uno standard, ogni app dovrebbe costruire un collegamento diverso per ogni servizio. L'MCP è uno standard aperto, proposto da Anthropic a fine 2024 e oggi supportato dai principali assistenti ed editor, che definisce un unico modo di farlo.

Metafora: l'MCP è la porta USB-C dell'AI. Prima ogni dispositivo aveva il suo caricatore; con una porta standard, qualsiasi accessorio funziona con qualsiasi dispositivo. Un server MCP scritto per Figma funziona con tutti gli assistenti compatibili.

Architettura client–server

È la stessa architettura client–server del web che conosci (il browser chiede, il server risponde), applicata all'AI:

Host + client MCP

L'app di AI che usi (un assistente, un editor, un agente da terminale). Contiene il client che parla con i server.

Server MCP

Piccoli programmi, uno per servizio, che espongono tool (azioni), risorse (dati da leggere) e prompt predefiniti.

Servizi e dati

GitHub, Figma, Google Drive, un database, le cartelle del tuo computer…

Esempi d'uso

  • GitHub: "Leggi le issue aperte del progetto e proponi come risolvere la più urgente."
  • Figma: "Leggi le variabili colore e tipografiche di questo file e generale come variabili CSS."
  • Database: "Quante iscrizioni ai corsi abbiamo ricevuto questo mese?"
  • Google Drive: "Trova il brief del cliente e riassumi i requisiti."
  • Filesystem: "Rinomina le foto della cartella mostra seguendo lo schema anno-titolo."
Sicurezza: un server MCP agisce con i tuoi permessi e può leggere i tuoi dati. Installa solo server di fonti affidabili (ufficiali o molto diffusi), concedi il minimo accesso necessario (es. una sola cartella, non tutto il disco) e fai attenzione ai contenuti esterni: una pagina web o un documento potrebbero contenere istruzioni nascoste rivolte all'AI (prompt injection).

Le skill

Le skill sono pacchetti di istruzioni riutilizzabili (spesso un file Markdown con eventuali script e modelli) che insegnano all'agente come svolgere un compito specifico: creare una presentazione con il layout dello studio, applicare le regole del design system, preparare il deploy del sito. Se l'MCP dà all'agente nuove mani, le skill gli danno nuove competenze. L'agente le carica solo quando servono, per non riempire la context window.

5. Agenti di Coding

Le categorie

Categoria Esempi Ideale per
Agenti da terminale Claude Code, Codex CLI, Gemini CLI Compiti su tutto il progetto: modifiche a più file, comandi, test, Git
Editor con AI integrata Cursor, GitHub Copilot (in VS Code), estensioni degli agenti per gli editor Lavorare sul codice con suggerimenti e chat, vedendo le modifiche riga per riga
Generatori di app e prototipi v0, Lovable, Bolt Prototipi rapidi da una descrizione o da uno screenshot, anche senza saper programmare

Il workflow consigliato

  1. Esplorare: chiedi all'agente di leggere il progetto e spiegarti come è organizzato, senza modificare nulla.
  2. Pianificare: fatti proporre un piano (quali file, quali modifiche) e correggilo prima che inizi.
  3. Implementare a piccoli passi: una funzionalità alla volta, non "tutto il sito" in un colpo.
  4. Rivedere il diff: leggi le modifiche riga per riga, come faresti con il lavoro di un collega.
  5. Testare: apri la pagina, prova su mobile, con la tastiera, nei casi limite.
  6. Commit: salva un punto di ripristino con un messaggio chiaro. Se il passo successivo va male, torni indietro. Vedi la Guida Git e GitHub.
Consiglio: lavora sempre in un progetto sotto Git. È la tua rete di sicurezza: qualsiasi cosa faccia l'agente, puoi vedere esattamente cosa è cambiato e annullarla.

5.1 Vibe Coding e i suoi Limiti

Il vibe coding è il modo di programmare "a sensazione": descrivi quello che vuoi, accetti il codice generato senza leggerlo e correggi solo guardando il risultato a schermo. È fantastico per prototipare un'idea in un pomeriggio, sperimentare, creare strumenti usa e getta.

Ma un sito che consegni a un cliente o all'esame è un'altra cosa: il codice consegnato va capito e revisionato. Un sito che "sembra funzionare" può nascondere problemi che a schermo non si vedono:

Accessibilità e semantica

<div> cliccabili al posto di <button>, immagini senza alt, form senza <label>, contrasti insufficienti, titoli fuori ordine.

Sicurezza

Query SQL costruite concatenando l'input dell'utente (SQL injection), input non validati lato server, password e chiavi API scritte nel codice e pubblicate su GitHub.

Manutenibilità

Codice duplicato, stili inline ovunque, librerie inutili, file enormi che nessuno (nemmeno l'AI, la volta dopo) riesce più a modificare.

Performance

Immagini pesantissime, script caricati in modo bloccante, animazioni che rallentano i telefoni economici.

// ❌ Generato "a sensazione": funziona, ma è vulnerabile a SQL injection
$sql = "SELECT * FROM utenti WHERE email = '" . $_POST['email'] . "'";

// ✅ Revisionato: query preparata, l'input non può diventare codice SQL
$stmt = $pdo->prepare('SELECT * FROM utenti WHERE email = ?');
$stmt->execute([$_POST['email']]);

Usa le Best Practices come checklist di revisione e la sezione Accessibilità di Base della guida HTML. Un buon metodo: chiedi a un secondo agente, in una sessione nuova, di fare la code review del codice scritto dal primo.

6.1 Stato Attuale dei Modelli

Stato a ottobre 2026

Queste informazioni cambiano ogni pochi mesi: verificale sempre sui siti ufficiali.

  • OpenAI: in ChatGPT è appena arrivata la famiglia GPT-6: GPT-6 Luna per gli utenti gratuiti, GPT-6 Sol per i piani a pagamento, GPT-6 Astra come opzione di ragionamento avanzato. Per il coding, l'agente Codex.
  • Google: la famiglia Gemini 3.x, con Gemini 3.8 Flash come modello rapido più recente, e Nano Banana per le immagini. Il nuovo Gemini 4 Argon è stato annunciato a fine settembre 2026, per ora con accesso limitato ad alcuni partner.
  • Anthropic: la famiglia Claude 5: Fable 5.1 (il più capace, per ragionamenti complessi e lavori lunghi), Opus 5.5 (il consigliato per la maggior parte dei compiti e per il coding), Sonnet 5.5 (equilibrio tra velocità e intelligenza) e Haiku 5.5 (il più veloce ed economico).
  • Open-weight: tra le famiglie più usate DeepSeek V4, Qwen 3.x (Alibaba), Mistral (europea), Llama 4 (Meta) e gpt-oss (OpenAI).

6.2 Modelli Open-Weight ed Esecuzione Locale

Un modello open-weight ("a pesi aperti") è un modello di cui il produttore pubblica i parametri: chiunque può scaricarlo ed eseguirlo sul proprio computer o server, nei limiti della licenza. Si dice open-weight e non open source perché di solito non vengono pubblicati i dati e il codice di addestramento.

Tra i produttori più noti: Mistral (francese, quindi europea), Meta (Llama), Alibaba (Qwen), DeepSeek, e anche OpenAI e Google con alcuni modelli più piccoli.

Eseguire un modello in locale

Programmi come Ollama o LM Studio rendono semplice scaricare e usare un modello sul proprio computer:

# Dopo aver installato Ollama, da terminale:
ollama pull mistral       # scarica il modello (alcuni GB)
ollama run mistral        # apre una chat nel terminale, tutto in locale
Vantaggi
  • Privacy: i dati non lasciano il tuo computer;
  • costi: nessun abbonamento o costo per richiesta;
  • funziona offline;
  • si può personalizzare e integrare liberamente.
Limiti
  • i modelli che girano su un portatile sono più piccoli e meno capaci di quelli in cloud;
  • servono molta RAM e possibilmente una buona scheda grafica;
  • niente ricerca web o strumenti, se non li configuri tu;
  • aggiornamenti e configurazione sono a tuo carico.

Quale scegliere?

Non esiste "il migliore" in assoluto: si sceglie in base al compito. Un modello veloce per le domande rapide, uno più potente per i ragionamenti complessi, un agente di coding per il progetto, un modello locale per i dati riservati. Prova gli stessi compiti su assistenti diversi (è il primo esercizio qui sotto) e costruisci la tua esperienza.
