Come usare questa pagina

Questa pagina è un ricettario: ogni sezione parte da un problema concreto ("perché il mio footer sta a metà pagina?") e mostra la soluzione, il perché funziona e, quando ci sono più strade, quale scegliere.

Non serve leggerla dall'inizio alla fine: tienila tra i segnalibri e torna qui quando ti blocchi. Le proprietà usate sono spiegate nella Guida CSS Base; per Flexbox e Grid ci sono le guide Flexbox in dettaglio e Grid in dettaglio.

Regola d'oro: prima di cercare una soluzione, apri i DevTools (tasto destro → Ispeziona) e guarda il box dell'elemento: margini, padding e dimensioni reali spiegano la maggior parte dei "misteri" del CSS.

Come centrare (orizzontale, verticale, entrambi)

"Come si centra un div?" è la domanda più famosa del CSS. La risposta giusta è sempre: dipende. Bisogna farsi due domande:

  1. Cosa sto centrando? Un elemento inline (testo, link, immagine, inline-block) o un elemento block (div, section, p...)?
  2. In quale direzione? Solo orizzontale, solo verticale o entrambe?

Nelle demo le linee rosa tratteggiate segnano il centro del contenitore.

Organizzazione ispirata a Centering in CSS: A Complete Guide di CSS-Tricks.

Centrare in orizzontale

a) Elementi inline o testo → text-align: center

text-align si applica al genitore e centra tutto il suo contenuto inline: testo, link, immagini, bottoni, elementi inline-block. Non centra un div!

.genitore {
    text-align: center;
}
Testo / inline

b) Un elemento block → margin: 0 auto

Un blocco occupa di default tutta la larghezza disponibile, quindi non c'è niente da centrare. Se gli dai una larghezza (width o max-width), i margini laterali auto si dividono lo spazio rimasto in parti uguali.

.contenitore {
    max-width: 960px;   /* Senza larghezza non funziona! */
    margin: 0 auto;     /* 0 sopra/sotto, auto a destra/sinistra */
}

/* Versione moderna con proprietà logiche */
.contenitore {
    max-width: 960px;
    margin-inline: auto;
}
Block con width
Attenzione: margin: auto non centra in verticale un elemento nel flusso normale: i margini verticali auto valgono 0. Funziona in verticale solo dentro Flexbox, Grid o con position: absolute (vedi sotto).

c) Più blocchi in fila → inline-block oppure Flexbox

/* Vecchio stile: i figli diventano "parole" */
.genitore { text-align: center; }
.figlio   { display: inline-block; }

/* Moderno: Flexbox */
.genitore {
    display: flex;
    justify-content: center;
    gap: 0.5rem;
}

Centrare in verticale

a) Padding uguale sopra e sotto

La soluzione più semplice e spesso dimenticata: se l'altezza del contenitore può dipendere dal contenuto, basta dare lo stesso padding sopra e sotto. Ottimo per bottoni, badge, banner.

.banner {
    padding-top: 60px;
    padding-bottom: 60px;
    /* oppure: padding-block: 60px; */
}
Padding uguale

b) Una sola riga di testo → line-height = altezza

Se il testo sta su una riga sola, impostare line-height uguale all'altezza del contenitore lo centra. È un trucco "storico": se il testo va a capo si rompe, quindi oggi si preferisce Flexbox.

.etichetta {
    height: 50px;
    line-height: 50px;  /* Uguale all'altezza */
}
Una riga sola

c) Qualsiasi contenuto → Flexbox con align-items

.genitore {
    display: flex;
    align-items: center;   /* Asse trasversale = verticale */
    min-height: 160px;     /* Serve un'altezza! */
}
align-items
Il motivo n°1 per cui "non si centra in verticale": il genitore è alto quanto il suo contenuto, quindi non c'è spazio in cui centrare. Dai al genitore un'altezza (min-height, 100vh, 100dvh...) e controlla nei DevTools quanto è alto davvero.

Centrare in orizzontale e verticale

1. Grid: place-items il più corto

.genitore {
    display: grid;
    place-items: center;
}
Grid

2. Flexbox: due proprietà il più usato

.genitore {
    display: flex;
    justify-content: center;
    align-items: center;
}
Flexbox

3. Flexbox + margin: auto

.genitore { display: flex; }
.figlio   { margin: auto; }
/* In un contenitore flex i margini auto
   assorbono lo spazio in tutte le direzioni */
margin: auto

4. Position absolute + transform

.genitore { position: relative; }
.figlio {
    position: absolute;
    top: 50%;
    left: 50%;
    transform: translate(-50%, -50%);
}
absolute

Perché nella tecnica 4 serve transform? top: 50% e left: 50% spostano l'angolo in alto a sinistra del figlio al centro. translate(-50%, -50%) lo riporta indietro di metà della sua larghezza e altezza, qualunque esse siano. Utile per elementi sovrapposti (un'icona "play" su un'immagine, un badge, una modale).

Variante: absolute + inset: 0 + margin: auto

.figlio {
    position: absolute;
    inset: 0;              /* top/right/bottom/left: 0 */
    margin: auto;
    width: fit-content;    /* Serve una dimensione */
    height: fit-content;
}
inset + auto

Footer sempre in fondo (sticky footer)

Il problema: in una pagina con poco contenuto (es. "Contatti") il footer sale e resta a metà schermo, con uno spazio vuoto sotto.

La soluzione: rendere il body alto almeno quanto lo schermo e far "allargare" il main per occupare lo spazio rimasto.

/* Con Flexbox */
body {
    min-height: 100dvh;       /* Almeno alto quanto lo schermo */
    display: flex;
    flex-direction: column;
    margin: 0;
}
main {
    flex: 1;                  /* Prende tutto lo spazio libero */
}

/* Oppure con Grid */
body {
    min-height: 100dvh;
    display: grid;
    grid-template-rows: auto 1fr auto; /* header, main, footer */
}

Footer: resta in fondo

dvh (dynamic viewport height) tiene conto delle barre del browser su mobile, che con 100vh causano un piccolo scroll indesiderato.

Immagini ribelli

L'immagine esce dal contenitore

Un'immagine larga 2000px in una colonna di 400px sborda. La regola da mettere in ogni progetto:

img, svg, video {
    max-width: 100%;   /* Mai più larga del contenitore */
    height: auto;      /* Mantiene le proporzioni */
}

Quei 4px misteriosi sotto l'immagine

Le immagini sono elementi inline: si appoggiano sulla linea di base del testo come se fossero una lettera, e sotto lasciano lo spazio per le "gambe" delle lettere (g, p, q). Ecco il bordo giallo sotto l'immagine:

Inline: spazio sotto
display: block: niente spazio 
img {
    display: block;            /* Soluzione 1: non è più inline */
}
/* oppure */
img {
    vertical-align: middle;    /* Soluzione 2: resta inline ma non usa la baseline */
}

L'immagine si deforma

Se imposti sia width sia height con proporzioni diverse dall'originale, l'immagine si schiaccia. Usa object-fit, che funziona come background-size ma per le <img>:

.card img {
    width: 100%;
    aspect-ratio: 4 / 3;   /* Tutte le immagini della griglia uguali */
    object-fit: cover;     /* Riempie e ritaglia senza deformare */
}

Scroll orizzontale indesiderato su mobile

Il problema: sullo smartphone la pagina "balla" a destra e sinistra. Qualcosa è più largo dello schermo. I colpevoli più frequenti:

  • width: 100vw: vw include la barra di scorrimento, quindi è più largo della pagina → usa width: 100%.
  • Un elemento con width fissa in pixel (es. width: 600px) → usa max-width.
  • width: 100% + padding senza box-sizing: border-box.
  • Immagini, video, iframe o tabelle senza max-width: 100%.
  • Parole o URL lunghissimi che non vanno a capo (vedi sezione successiva).

Per trovare il colpevole, incolla temporaneamente questa regola: ogni elemento viene contornato e quello che sborda salta all'occhio.

/* DEBUG: da togliere a fine lavoro! */
* {
    outline: 1px solid red;   /* outline non occupa spazio, a differenza di border */
}
Evita il "cerotto" body { overflow-x: hidden; }: nasconde il sintomo ma non la causa, e può rompere position: sticky. Se proprio serve, preferisci overflow-x: clip.

Testo troppo lungo

Tagliare con i puntini di sospensione (una riga)

.titolo-card {
    white-space: nowrap;      /* Niente a capo */
    overflow: hidden;         /* Nasconde l'eccedenza */
    text-overflow: ellipsis;  /* Aggiunge "…" */
}

Un titolo di articolo davvero molto lungo che non ci sta

Tagliare dopo N righe

.anteprima {
    display: -webkit-box;
    -webkit-box-orient: vertical;
    -webkit-line-clamp: 2;    /* Numero di righe */
    line-clamp: 2;
    overflow: hidden;
}

Anteprima di un articolo: il testo prosegue per diverse righe, ma nella card ne vogliamo mostrare solo due e poi i puntini di sospensione.

I prefissi -webkit- sembrano vecchi ma sono il modo supportato da tutti i browser.

Parole lunghe e URL che sbordano

.contenuto {
    overflow-wrap: break-word;  /* Spezza la parola solo se non ci sta */
    hyphens: auto;              /* Sillabazione (richiede lang="it" su <html>) */
}

Margini che "spariscono" (margin collapse)

Il problema 1: due paragrafi uno sotto l'altro, il primo con margin-bottom: 30px, il secondo con margin-top: 20px. Ti aspetti 50px di distanza, invece sono 30px.

Perché: i margini verticali di blocchi adiacenti si fondono (collapse): vince il più grande. È voluto, serve a tenere uniforme lo spazio tra paragrafi.

Il problema 2: metti margin-top al primo figlio di una card e invece di spostare il figlio dentro la card... sposta giù tutta la card! Il margine del figlio "esce" dal genitore.

/* Soluzioni per il problema 2 (sul genitore) */
.card { padding-top: 1px; }        /* Qualsiasi padding o border blocca il collapse */
.card { display: flow-root; }      /* Crea un nuovo contesto: soluzione "pulita" */
.card { display: flex; flex-direction: column; } /* Flex e grid non fanno collapse */

/* Prevenzione: usa margini in una sola direzione */
h2, p, ul { margin-top: 0; margin-bottom: 1rem; }

/* Oppure gestisci lo spazio dal genitore */
.card { display: flex; flex-direction: column; gap: 1rem; }
Buona abitudine: dentro Flexbox e Grid usa gap invece dei margini per distanziare gli elementi: niente collapse, niente margine in più sull'ultimo elemento.

Card della stessa altezza con il bottone in fondo

Il problema: in una fila di card i testi hanno lunghezze diverse, e i bottoni "Scopri di più" finiscono ad altezze diverse.

La soluzione: la griglia rende le card alte uguali (comportamento di default stretch); dentro ogni card una colonna flex e margin-top: auto sul bottone lo spingono in fondo.

.griglia-card {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 1rem;                 /* Le card sono già alte uguali */
}

.card {
    display: flex;
    flex-direction: column;
}

.card .bottone {
    margin-top: auto;          /* Assorbe lo spazio libero sopra di sé */
}

Bonus: l'elemento flex che non si restringe

Un testo lungo o un <pre> dentro un elemento flex fa sbordare tutta la riga? Gli elementi flex hanno min-width: auto, cioè non scendono sotto la larghezza del loro contenuto. Si sblocca così:

.item-flex {
    flex: 1;
    min-width: 0;   /* Ora può restringersi (e il testo può andare a capo o fare ellipsis) */
}

Griglia responsive senza media query

Una riga di CSS che decide da sola quante colonne entrano: ogni colonna è larga almeno 250px, e se lo spazio non basta gli elementi vanno a capo. Ridimensiona la finestra per vederla funzionare.

.galleria {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(min(250px, 100%), 1fr));
    gap: 1rem;
}
/* min(250px, 100%) evita lo sbordo su schermi più stretti di 250px */

Video e iframe responsive

Il codice di embed di YouTube o Vimeo ha width="560" height="315" fissi: su mobile sborda, o se metti width: 100% l'altezza resta 315px e il video si deforma con le bande nere.

iframe,
video {
    width: 100%;
    height: auto;
    aspect-ratio: 16 / 9;   /* L'altezza si calcola dalla larghezza */
}

Nei vecchi tutorial troverai il "trucco del padding" (padding-top: 56.25% su un contenitore): aspect-ratio lo sostituisce ed è supportato da tutti i browser moderni.

z-index non funziona

Hai messo z-index: 9999 e il menu resta comunque sotto l'immagine? Le cause sono quasi sempre due.

1. L'elemento non è posizionato

z-index funziona solo su elementi con position diverso da static (o figli di flex/grid).

.menu {
    position: relative;   /* Senza questa riga z-index viene ignorato */
    z-index: 10;
}
z-index: 1
z-index: 3
z-index: 2

2. Lo stacking context del genitore

Alcune proprietà (z-index + position, opacity minore di 1, transform, filter, isolation: isolate...) creano un contesto di sovrapposizione: i figli competono solo tra loro. Un figlio con z-index: 9999 dentro un genitore con z-index: 1 resta sotto un elemento esterno con z-index: 2. È come un foglio in una cartellina: puoi metterlo in cima alla cartellina, ma non sopra un'altra cartellina.

Consiglio: usa una scala piccola e ordinata (es. 1 contenuti sovrapposti, 10 header, 100 menu, 1000 modali) salvata in variabili CSS, invece di numeri a caso sempre più grandi. Approfondimento in Guida CSS Base → Posizionamento.

Header fisso che copre le ancore

Il problema: con un header position: fixed o sticky, cliccando un link interno (href="#contatti") il titolo della sezione finisce nascosto sotto l'header.

html {
    scroll-behavior: smooth;     /* Scorrimento animato (opzionale) */
}

/* Lascia spazio sopra le sezioni quando ci si arriva con un'ancora */
section[id],
h2[id] {
    scroll-margin-top: 80px;     /* Altezza dell'header + un po' di respiro */
}

E se position: sticky non si "attacca"?

  • Manca la soglia: serve top: 0 (o un altro valore).
  • Un antenato ha overflow: hidden, auto o scroll: lo sticky si attacca a quel contenitore, non alla pagina.
  • Il genitore è alto quanto l'elemento: lo sticky resta "incollato" solo dentro il proprio genitore, se non c'è spazio per scorrere non si vede l'effetto.

L'ultima riga è la più utile per l'accessibilità: testo invisibile ma letto dagli screen reader, ad esempio un'etichetta per un bottone con sola icona. Bootstrap la offre già come classe .visually-hidden; senza Bootstrap:

.visually-hidden {
    position: absolute;
    width: 1px;
    height: 1px;
    padding: 0;
    margin: -1px;
    overflow: hidden;
    clip: rect(0, 0, 0, 0);
    white-space: nowrap;
    border: 0;
}
<button class="btn-icona">
    <i class="bi bi-search" aria-hidden="true"></i>
    <span class="visually-hidden">Cerca</span>
</button>

Kit di debug: quando "non funziona"

Prima di riscrivere tutto, segui questa checklist nell'ordine:

  1. Il CSS è caricato? DevTools → scheda Network o Sources: il file c'è? Il percorso nel <link> è giusto (maiuscole comprese, su un server online contano)?
  2. Il selettore prende l'elemento? Ispeziona l'elemento: se la tua regola non compare nel pannello Styles, il selettore è sbagliato (classe scritta male, punto mancante, # al posto di .).
  3. La regola è barrata? Allora un'altra regola più specifica (o scritta dopo) vince: vedi Cascata e Specificità.
  4. La proprietà ha l'icona ⚠️? Valore non valido: un errore di battitura, un'unità mancante (width: 100 invece di 100px), un punto e virgola dimenticato sulla riga precedente.
  5. La proprietà è "inattiva"? Chrome e Firefox mostrano un avviso se la proprietà non ha effetto in quel contesto (es. justify-content senza display: flex, z-index senza position, width su un elemento inline).
  6. La cache? Ricarica forzata con Ctrl + F5 (Cmd + Shift + R su Mac).
